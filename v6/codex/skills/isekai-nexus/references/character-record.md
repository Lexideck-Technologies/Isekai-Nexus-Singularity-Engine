# Character record agreement

Evaluation turns accepted intake into a proposed build. Acceptance makes that revision available to arrival and play. Keep the active campaign, intake sketch, proposed build, and accepted build distinct.

| Field | Required content |
|---|---|
| Identity | Accepted name, origin, story facts, motivation |
| World and start | Full document identity/version, selected variant, arrival location |
| Current power | Level, rank, usable capacity; existing traveler values preserved |
| Expertise | Memories and trained techniques, distinct from current capacity |
| Class and package | Class concept, chosen synthesis mode, allocated talents and skills |
| Ability terms | Trigger, effect, capacity, costs, limits, growth, owner of each effect |
| Personal system | Default or accepted variant; promises, personality, conditions, manifestation, agency |
| Recovery | Sealed abilities and concrete release conditions |
| Attributes and resources | Known numbers and their rules, or descriptive profiles; accepted numeric calibration if introduced |
| Assets | Exact start kit, funds, access, anchor, blessings; record debts only when actually accepted |
| Relationships | Start contacts, affiliations, commitments, and known context |
| Opening | Chosen start's first opportunity and immediate situation |
| Acceptance | Proposed/accepted revision, pending decision, unchanged fixed facts |
| Allocation identity | One identity for starting allocation; record its application once |

Use the record as shared state, not a compulsory player-facing form. Do not fabricate missing historical stats for an existing traveler. Ask for the material missing fact or retain it as unresolved until relevant.

## Agreement across routes

Background -> Ingestion -> Evaluation and Background -> World Building -> Ingestion -> Evaluation preserve the same accepted facts. Supplied-world and explicitly original-world routes preserve the same system promise; generated additions can change its world-native implementation only with acceptance of a defining change.

Evaluation -> interruption -> Evaluation preserves allocation identity and the pending decision. Evaluation -> world revision -> Evaluation rechecks dependent facts without granting another kit. Arrival reads the accepted record; it cannot quietly replace talents, rank, kit, or obligations.

## Arrival boundary

Use [Arrival](../../isekai-arrival/SKILL.md) after build acceptance. It reads the existing allocation, creates a tailored entry episode, and stops at the first player action. First opportunities remain opportunities: no automatic combat victory, payment, title, or level-up before the player acts and [Resolution](../../isekai-resolution/SKILL.md), [Progression](../../isekai-progression/SKILL.md), and the relevant activity covers run.
